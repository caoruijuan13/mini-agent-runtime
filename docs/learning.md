# 第一阶段：一次模型调用

目标：理解一次调用的输入是什么、输出是什么，模型和调用它的程序分别负责什么。
当前状态：学习者已确认学习验收通过（2026-10-29）。代码验证与学习验收分别记录。

## 先回答问题

- `messages` 为什么是列表？每条消息的 `role` 和 `content` 表达什么？
包括历史记录，role表达用户/助手/工具，content是内容。
- 调用模型与执行普通函数，在输入输出上有哪些相同点？
普通函数是确定性输出，调用模型只能保证接口正确，但不保证内容。
- Mock 替代了什么？它能验证协议，为什么不能验证模型能力？
替代真实模型，返回预设结果。可以验证消息是否组装正确、调用流程和结果处理是否符合协议，但不是真实模型，所以无法验证模型能力。
- 模型返回一段文本后，应该由谁决定展示、保存或继续调用？
调用它的应用程序（runtime／编排层）决定下一步：展示给用户、保存到历史、还是继续调用模型/工具

## 最小实验范围

只研究一条用户消息、一次模型调用和一条文本响应。
先写出预期输入输出，再由学习者决定是否生成或修改代码。
本阶段不要求工具调用、执行循环、HTTP、流式、持久化或并发。

已有 `python/agent/mock.py` 可作参考，但其中的 `add` 分支属于后续工具主题。
如需观察文本路径，可运行：

```bash
bash scripts/run_demo.sh '你好' --trace
```

这个命令借助已有 Runtime 展示事件；无需先理解整套实现，更不要求直接接受其设计。
