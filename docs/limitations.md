# 已知边界

本项目首先是教学和实验运行时，不是开箱即用的生产模型网关。

## 功能边界

- Python CLI 的最终文本流是本地逐字符显示，不是真正端到端模型流。
- Rust 流式解析不组装 `delta.tool_calls`。
- SSE 响应不传递 Token usage。
- Rust 与 Python 的工具 Schema 需要人工同步。
- 工具结果和错误都是普通字符串。
- 会话只保存在 Python 进程内，重启即丢失。

## 可靠性边界

- 没有统一超时预算。
- 没有重试、退避、熔断或 Provider 降级。
- 没有并发上限、队列和背压策略。
- 没有客户端断开到上游请求的完整取消传播。
- `/health` 不验证真实 Provider 是否可用。
- 上游失败统一返回 HTTP 500。

## 安全边界

- 没有认证和租户隔离。
- CORS 当前允许任意来源。
- 没有请求体、消息数量和上下文长度上限。
- 计算工具不是面向不可信输入的强隔离沙箱。
- 错误正文可能包含过多上游信息。

## 可观测性边界

- 只有基础 Tracing 日志。
- 没有 Prometheus 指标。
- 没有跨 Python、Rust、Provider 和工具的分布式 Trace。
- 没有稳定错误分类、SLO 或告警。

## 性能证据边界

- 默认报告来自单机 Mock 服务。
- CPU/RSS 为 `ps` 的尽力采样。
- 没有 GPU、KV Cache、批处理或模型质量指标。
- 本地短时基准不能外推为生产容量。

## 推荐演进顺序

1. 实现真正端到端 SSE 和流式工具调用。
2. 增加结构化错误、超时、取消和输入限制。
3. 增加 Metrics、Trace 和请求关联 ID。
4. 增加并发控制、背压、重试和熔断。
5. 抽象多 Provider 路由与成本统计。
6. 接入 vLLM 等推理服务，另建真实推理基线。
