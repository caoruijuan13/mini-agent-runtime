# 已知边界

本项目首先是教学和实验运行时，不是开箱即用的生产模型网关。

## 功能边界

- Python CLI 的最终文本流是本地逐字符显示，不是真正端到端模型流。
- Rust 流式解析不组装 `delta.tool_calls`。
- SSE 响应不传递 Token usage。
- Rust 与 Python 的工具 Schema 需要人工同步。
- 工具结果和错误都是普通字符串。
- 会话只保存在 Python 进程内，重启即丢失。

## 可靠性边界

- 没有统一超时预算。
- 没有重试、退避、熔断或 Provider 降级。
- 没有并发上限、队列和背压策略。
- 没有客户端断开到上游请求的完整取消传播。
- `/health` 不验证真实 Provider 是否可用。
- 上游失败统一返回 HTTP 500。

## 安全边界

- 没有认证和租户隔离。
- CORS 当前允许任意来源。
- 没有请求体、消息数量和上下文长度上限。
- 计算工具不是面向不可信输入的强隔离沙箱。
- 错误正文可能包含过多上游信息。

## 可观测性边界

- 只有基础 Tracing 日志。
- 没有 Prometheus 指标。
- 没有跨 Python、Rust、Provider 和工具的分布式 Trace。
- 没有稳定错误分类、SLO 或告警。

## 性能证据边界

- 默认报告来自单机 Mock 服务。
- CPU/RSS 为 `ps` 的尽力采样。
- 没有 GPU、KV Cache、批处理或模型质量指标。
- 本地短时基准不能外推为生产容量。

## 推荐演进顺序

按[学习与优化路线图](roadmap.md)分阶段推进：

1. 理解链路，重新建立 QA 与 Mock 性能基线。
2. 统一执行循环，实现端到端 SSE 和流式工具调用。
3. 增加结构化错误、超时、取消和工具执行边界。
4. 增加持久化、崩溃恢复和幂等策略。
5. 完善可观测性、并发控制、背压并验证优化收益。
6. 建立真实模型任务评测，再选择运行时、服务基础设施或推理服务方向。

上述能力均为计划；完成实现和验证后再更新本页边界。
